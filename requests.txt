SHARED SPEC
-----------
- Format: GIF (or animated WebP named .gif if the encoder allows; GIF preferred for max support).
- Loop: infinite. No audio.
- Target size: <= 500 KB each, <= 800 KB hard ceiling.
- Frame rate: 12-15 fps, smooth enough for motion but small.
- Duration: 3-6 s per loop. Keep the key idea readable in the first 2 s.
- Background: transparent OR match the app surface `#faf9f5`. If matching, keep a 1px inset so
  the app's own rounded border reads on top.
- Palette (must match the app tokens):
    Lane A accent (purple)  #aa3bff

- Draw roads/nodes in the SAME schematic layout as the app (see `src/romania.ts` COORDS) so the
  GIF reads as "the same map".
- Font for any labels: a monospace (Geist Mono / ui-monospace). Keep labels >= 12px at display size.
- Deliverable dimensions below are display-intent; the sidebar shows them at ~330 px wide
  (2x that for retina: e.g. deliver 720x460 for a "720x460 @ 330 display" card).

- Start = Arad (green start ring), Goal = Bucharest (red goal ring).
- Animate UCS: expanding cost contours rippled outward from Arad in every direction (west, north,

Key idea to communicate: uniform-cost search has no idea where the goal is -> explores all sides.

GIF-3  gifs/admissible-consistent.gif
--------------------------------------------
Caption: "Admissible = h never pokes above the true cost. Consistent = it can only rise by as much
as a road costs."
Canvas: 720x460. Mostly a diagram, not the whole map.
Content (two beats):
  Beat 1 - Admissibility: a bar chart / number line where "true cost h*" is a fixed bar and the
  candidate "h" bars for several nodes sit at or BELOW it. One inadmissible bar (above h*) flashes
  red and is crossed out. Label "h(n) <= h*(n)".
  Beat 2 - Consistency: three nodes n -> n' with road cost c. Show h(n), h(n') and c; animate the
  inequality h(n) <= c + h(n'). A road arrow "c" slides in to show the bound still holds.
Key idea: admissible = optimistic; consistent = the estimate cannot drop by more than the road.

GIF-4  gifs/lp-vector-decomposition.gif
--------------------------------------------
Caption: "The chord a->b rewritten as a combination of road vectors; the LP prices that combination."
Canvas: 720x460.
Content:
- Two cities a and b highlighted; draw the straight CHORD a->b as a dashed gold line (label it
  "chord_ab"). Add a small annotation "never measured directly (that's SLD)".
- Show three or four actual roads near the path as coloured vectors vec_i with lengths = km_i.
- Animate solving: the coloured vectors slide/scale into place tip-to-tail until they exactly
  span the chord; a "cost = sum alpha_i * km_i" readout counts up to the LP optimum, and it stays
  visibly SHORTER/fake-cheaper than the real path (that's what makes it a lower bound).
- Add a tiny "0 <= alpha_i <= 1" constraint label.
Key idea: any real route's vectors must span the chord, so the cheapest such combination is a
lower bound on the true distance.

GIF-5  gifs/alt-triangle-inequality.gif
--------------------------------------------
Caption: "Any real route through the landmark is at least as long as the difference the landmark
certifies."
Canvas: 720x460.
Content:
- Map with a landmark L (e.g. Eforie, far corner) marked with a star.
- A node n and the goal g. Draw: real road route n -> g (green), plus two dotted reference
  routes L->n and L->g with their km distances shown.
- Animate the inequality d(n,g) >= |d(L,n) - d(L,g)|: show the two dotted distances and highlight
  their absolute difference as a guaranteed lower bound on the green route.
- Second beat: add a second landmark and show the bound GROW (take the max) -> "more landmarks =
  tighter".
- Optional callout: "L is a dead-end and g is its only neighbour -> bound is EXACT."
Key idea: triangle inequality turns precomputed landmark distances into an admissible bound, using
only road km.

GIF-6  gifs/ensemble-max.gif
--------------------------------------------
Caption: "Each bound certifies 'the answer is at least this much'; the max keeps the strongest."
Canvas: 720x460.
Content:
- For a single node n: two vertical gauges/flasks labelled "h_LP" (purple) and "h_ALT" (teal),
  each filling to its value, both below a marked "true cost h*" line.
- Animate the two values over a few nodes; sometimes LP is taller, sometimes ALT. A "max" bracket
  snaps to the taller bar each time and a third bar "h = max(LP, ALT)" shows the result.
- Add a small guarantee stamp: "admissible: both <= h*  =>  max <= h*  ✓".
Key idea: the ensemble is admissible by construction and never weaker than either component.
